# Desktop accessibility and focus audit

Reviewed the keyboard-led game in desktop Chromium. This is an issue audit, not a WCAG 2.2 conformance assessment. Touch-only gameplay is outside product scope, and so is the file-manager view below 1024 CSS px (`docs/adr/0001-keyboard-and-viewport-floor.md`); the cinematic surfaces remain reflow-safe and in scope for browser zoom. Findings below describe the pre-fix build.

## Other findings

- **P1 — Current item, marked selection, and status feedback.** `FileSystemPane.tsx` exposes a named list and `FileSystemItem.tsx` marks the current row with `aria-current`. DOM focus remains outside that list during play; there is no active-descendant or focused-row mechanism to communicate movement. `[VIS]`, clipboard icons, and visual emphasis are not a named selection state. `SystemAlerts.tsx` renders notifications without a live-region role, unlike `ThreatAlert.tsx` and `SuccessToast.tsx`. Provide programmatic selection/cursor semantics and announce consequential updates once, not timer ticks or each typewriter character. WCAG 1.3.1, 4.1.2, 4.1.3.
- **P2 — Dim functional instructions and symbolic keys.** The intro’s continue hint is intentionally dim during typing, and some action hints still use faint zinc colors (`EpisodeIntro.tsx`, `WarningModal.tsx`, `ConfirmationModal.tsx`, `OutroSequence.tsx`). Check final contrast across opacity and backgrounds; preserve readable text when active. Help keycaps retain visible aliases; verify their pronunciation with a screen reader. WCAG 1.4.3 review.
- **Review — Timers and media.** `useGameTimer.ts` pauses for some overlays; the audit did not establish an accommodation for mandatory timed objectives or whether the essential-timing exception applies (2.2.1). `OutroSequence.tsx` uses a muted teaser video without a track. Verify whether it conveys unique information before deciding what text or media alternative is needed (1.2.1). Image previews use filenames as alt text; check whether meaningful image content needs a better equivalent (1.1.1).

## Verified improvements

- Help exposes a named modal, a visible Close button, and grouped commands. Chromium Tab/Shift+Tab stayed inside; Escape closed it and restored the Help button. The E2E assertions also verified `j`/`k` scroll the actual panel.
- Help fit without horizontal overflow at 1440×900, 1024×768, and 720×450. The Close button measured 26 CSS px high. These are viewport checks, not OS/browser zoom measurements.
- The first episode announces the facility date as text, and the intro offers a visible Skip Intro control. System monospace is consistent across body, intro heading, and Help.
- Unit and gameplay tests exercised intro/BIOS, Help, Map, Hint, search/filter, overwrite/delete, threat, game-over, and cycle paths; gameplay tests are not accessibility tests for all those surfaces.

### Major findings remediation

- The file browser owns gameplay keys and exposes the current file and marked selections separately. Within it, Tab opens file info; Tab or Esc closes it. Shift+Tab from the file browser reaches the toolbar without changing the current file.
- Help, Quest Map, Hint, and file info take focus and return it on close. Delete and overwrite start on the non-destructive choice; Enter activates the focused button, and the letter shortcuts still work. Warning and game-over actions are keyboard-focusable.
- Search via fd, filter, create, rename, fzf, and zoxide use labelled text fields. The fuzzy combobox exposes the highlighted result and keeps focus in the query while navigating results with the arrow keys.
- The OS motion preference and the in-game Minimal preset stop decorative CSS motion and show cinematic text immediately. Reduced suppresses the scanline and automatic gameplay glitches; the optional teaser requires explicit playback in the static mode.
- Both cinematics fit the window instead of the content. The opening keeps its header, progress bar, and `Shift+Enter` prompt outside the scroll region, which holds a 96 px floor; below roughly 330 px of height the overlay itself scrolls rather than clipping the prompt. The ending pins only its prompt: the heading and log scroll inside the region. Verified at 320×256 (the 400% reflow case), 320×450, 720×450, and 1280×800; PageDown scrolls either log by keyboard.
- The ending advance prompt moved from `zinc-500` at 4.35:1 to `zinc-300` at 14.21:1 against black and no longer pulses, so the only instruction on screen stays readable.
- At 320×450 CSS px, the search and fuzzy inputs were visible and unobstructed, and the Quest Map title cleared the toolbar. The opening `Shift+Enter` prompt measured 14.21:1 against black. Reduced motion preserved the May 31, 2015 date and `Shift+Enter` progression.

## Limits and next pass

No assistive-technology session, real browser zoom, flash analysis, external media review, or cross-browser accessibility comparison was performed. Verify screen-reader announcements, actual zoom, timed objectives, and media alternatives separately before claiming conformance.
